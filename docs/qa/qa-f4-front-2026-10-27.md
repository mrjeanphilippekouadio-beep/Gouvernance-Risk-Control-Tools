## 3. Observations (aucune ne bloque)

- **QA-F4-FR-01 MINOR** (`backend/src/services/UserService.ts:267`) : le message de refus de l'auto-suspension est en anglais (« You cannot suspend your own account — ask another admin ») et s'affiche tel quel dans la fenêtre d'une interface française, au-dessus du texte français. Le refus est bien visible (c'est le but du point 1.4) ; seule la langue est incohérente. Le frontend affiche volontairement le message du serveur (`UsersAdmin.tsx`, `describeError`), donc le correctif est côté serveur (message) ou une table de traduction côté écran. Même constat pour les autres messages métier du service (« Cannot remove the last member of the Risk Manager group », `RoleService.ts:641`).
- **Écart de brief** : la route d'audit est `GET /api/v1/audit-log` (singulier, `server.ts:593`), pas `/audit-logs` ; `/audit-logs` répond 404. Le script utilise la bonne route. Le filtre `entityType` + `entityId` passe par `listForEntity` et ignore `limit` (comportement connu).
- **Piège de test (pas un défaut)** : le CSS met les libellés de champ du formulaire de profil en majuscules ; `innerText` renvoie « COMBIEN DE PERSONNES… ». Le script compare le `textContent`. Une première exécution avait signalé deux libellés manquants (Q1, Q2) pour cette seule raison.
- **Piège de test** : les fenêtres du design system sont des `<dialog>` natifs ; `[role=dialog]` ne les trouve pas (rôle implicite), utiliser `dialog[open]`.
- `GET /users` est borné à `limit` ≤ 100 (200 → 400) : la pagination de l'écran (`ADMIN_PAGE_SIZE = 100`) est cohérente.

## 4. Limites

- Pas de soumission ni de confirmation d'un profil d'organisation (le brief demande l'affichage et le questionnaire seulement) ; pas de désignation effective.
