### QA-IRT3-04 — INFO : un envoi abandonné ne change pas le code de sortie
À l'échéance avec un envoi bloqué, le process sort en 0 (le journal compte l'abandon). Seuls les requêtes coupées ou le pool non fermé donnent 1. Conforme à la règle annoncée, mais une notification obligatoire perdue n'est visible que dans le journal : à confirmer par A10/A23 que cela suffit (alerte sur « abandoned > 0 »).

### QA-IRT3-05 — INFO : fermeture du pool après l'échéance
Si l'échéance est déjà passée quand `pool.end()` démarre, il reçoit un budget de 0 ms (course avec un timer nul). Observé : il gagne (exit 0) pool inactif ; le cas « pool.end dépassé -> exit 1 » est couvert au niveau unitaire (`Shutdown.test.ts`) mais non provoqué en process réel (nécessite une connexion bloquée).
