## 3. Observations (aucune ne bloque)

- **QA-F5A-01 MINOR** (`frontend/src/features/governance/GovernanceDecisionsPage.tsx:47-58` et `:97`) : un refus du serveur sur Confirmer (aucune fenêtre ouverte) passe par `setError`, affiché sous le titre « Chargement impossible » alors que le chargement a réussi (capture `08-echeance-depassee.png`). Le bandeau est en haut de page, au-dessus du tableau : avec de nombreuses lignes, il est hors de vue du bouton cliqué. Le refus n'est pas avalé, seul le libellé est trompeur. Le message est en anglais dans une interface française (même constat que QA-F4-FR-01).
- **QA-F5A-02 MINOR** (`GovernanceDecisionsPage.tsx:17-20`, `:81`) : avec `audit.read`, « Acceptée par » affiche l'identifiant brut du compte (`f5a0f5a0-0000-4000-8000-00000000000a`), pas un nom : le serveur ne renvoie que l'id (`GovernancePrincipleAcceptanceService.ts:56-65`). Illisible pour un auditeur ; à arbitrer (résolution du nom côté API ou annuaire côté écran). Autre point lié : une acceptation PENDING dont l'échéance est passée garde ses boutons Confirmer/Rejeter ; seul le serveur la refuse (`GovernancePrincipleAcceptanceService.ts:201`). Pas de libellé « Expirée ».
- **QA-F5A-03 INFO** (hors périmètre F5a) : l'écran d'arrivée (Cartographie) d'un compte sans `risk.read` appelle `/risks` et `/cartography/scale` et reçoit 4 fois 403 (console). Sans lien avec la page testée.
