## Constats

### SEC-L1-01 LOW 2,2 : le filtre de marquage s'applique aussi aux contrôles de séparation des tâches qui lisent `listForEntity` (échec ouvert)

- CVSS 3.1 : `AV:N/AC:H/PR:H/UI:N/S:U/C:N/I:L/A:N` = 2,2. Statut : REMEDIATION_REQUIRED (A06), avant la PR.
- Fichier : `backend/src/infrastructure/database/postgres/PostgresAuditRepository.ts:114` (`listForEntity`, et par cohérence
  `:123` `listRecent` et `:130` `search`).
- Constat : le cadrage §8.2 réserve le filtre aux lectures de **consultation** et laisse les lectures **techniques** non
  filtrées. Or `AuditRepository.listForEntity` n'est pas lu seulement par `AuditLogService` (consultation). C'est aussi la
  source de plusieurs contrôles :
  - `backend/src/services/RiskFrameworkService.ts:1101` `authoredByMe` (F-B6d-01 : exclusion « rôle créé ou élargi par le demandeur ») ;
  - `backend/src/services/RiskFrameworkService.ts:1226` et `:1232` `authorsOf` (maker-checker : auteurs d'une version et de son échelle DRAFT) ;
  - `backend/src/services/TenantService.ts:111` `reactivate` (le super-admin qui a désactivé ne peut pas réactiver) ;
  - `backend/src/services/ProcessService.ts:262` `championSelfDesignated` (marqueur d'exception q166/q176 affiché) ;
  - `backend/src/services/RiskImportService.ts:138` `previousImport` (avertissement de réimport, sans enjeu de sécurité).
- Scénario : l'admin A a créé il y a plus de 10 ans un rôle portant une permission d'administration. Le propriétaire de la
  base lance `mark_expired_audit_log`. `authoredByMe` ne voit plus le `CREATE` de A : son propre rôle compte alors comme
  « administrateur préexistant », et F-B6d-01 est contourné. Même mécanique pour un tenant désactivé il y a plus de 10 ans
  (réactivation par le même super-admin) et pour un marqueur d'exception de gouvernance qui disparaît de l'écran du processus.
- L'exploitabilité est faible (lignes de plus de 10 ans, marquage manuel par le propriétaire), mais le défaut est de
  conception : « consultation » a été traduit par « méthode du dépôt », alors que le même point d'entrée sert de preuve à
  des contrôles.
- Correctif minimal : ne filtrer que le chemin `GET /audit-logs`. Par exemple trois variantes filtrées (ou une option
  `{ hideRetained: true }`) appelées uniquement par `AuditLogService` ; `listForEntity` reste non filtré pour les services.
  Adapter `backend/test/Migration095.test.ts` (« only the three consultation reads filter ») pour vérifier que seul
  `AuditLogService` appelle les variantes filtrées.
- Test de régression : sur base live, poser une ligne `Role CREATE` du demandeur vieille de plus de 11 ans et lancer le
  marquage. La sollicitation F-B6d-01 doit rester refusée, et `AuditLogService.listForEntity` ne doit plus montrer la ligne.

### SEC-L1-02 LOW 2,7 : le `.down.sql` détruit la trace des marquages sans garde

- CVSS 3.1 : `AV:N/AC:L/PR:H/UI:N/S:U/C:N/I:L/A:N` = 2,7. Statut : décision A07 + HUMAN, non bloquant.
- Fichier : `database/postgresql/migrations/095_audit_log_retention_marks.down.sql:9` (`DROP TABLE IF EXISTS audit_log_retention_marks`).
- Constat : la garde protège contre UPDATE, DELETE et TRUNCATE, pas contre `DROP TABLE` (DDL). Le rollback efface la seule
  trace de qui a marqué quoi et quand, et refait apparaître dans les écrans toutes les lignes échues. Les lignes
  `audit_log` ne sont pas touchées : aucune preuve d'origine n'est perdue. C'est la preuve **de l'opération de
  conservation** qui disparaît.
- Correctif minimal (au choix) : le `.down.sql` refuse de s'exécuter si la table contient au moins une ligne
  (`DO $$ BEGIN IF EXISTS (SELECT 1 FROM audit_log_retention_marks) THEN RAISE EXCEPTION ...`, même pattern que le down V4),
  ou il exige un export préalable documenté dans le runbook. Garder le comportement actuel reste possible, à condition que
  ce soit une décision tracée.
- Note : l'ordre « retirer le filtre du code AVANT le down » est bien documenté (en-tête du down). Sans cela, les trois
  lectures tombent en erreur 500 : échec fermé, sans fuite.

### SEC-L1-03 INFO : une table temporaire peut ombrer la table de marques dans la session applicative

- CVSS 3.1 indicatif : `AV:N/AC:H/PR:H/UI:N/S:U/C:N/I:L/A:N` = 2,2. Classe préexistante, pas introduite par le lot.
- Fichier : `backend/src/infrastructure/database/postgres/PostgresAuditRepository.ts:102` (`NOT_MARKED`, nom non qualifié).
- PoC (local) : sous `SET ROLE grc_app_runtime` (`TEMP` est accordé à PUBLIC par défaut), créer
  `CREATE TEMP TABLE audit_log_retention_marks (audit_log_id uuid)` puis y insérer des ids. La requête du dépôt masque alors
  des lignes non marquées et réaffiche la ligne réellement marquée (lignes visibles : 2 → 1). L'effet persiste sur la
  connexion du pool.
- Pourquoi INFO : il faut déjà exécuter du SQL arbitraire sous le rôle applicatif. Dans ce cas, `audit_log` lui-même peut
  être ombré de la même façon (ses lectures n'ont jamais été qualifiées), et le rôle peut insérer des lignes forgées.
  Défense en profondeur possible : qualifier `public.audit_log_retention_marks` (et `public.audit_log`) dans les trois
  lectures, ou `REVOKE TEMP ON DATABASE ... FROM PUBLIC` (A09/A07).

### SEC-L1-04 INFO (A23) : `marked_by` désigne un rôle de base partagé

- `marked_by = current_user` donne `grc_migrator_runtime` ou le propriétaire Neon, pas une personne. L'imputabilité réelle
  dépend de qui détient ce secret (workflow `migrate.yml` approuvé, éditeur SQL Neon). Suggestion : consigner chaque
  lancement (run_id, opérateur humain, date) dans `ACTION_ITEMS.md` ou le runbook. Aucun changement de code demandé.

### SEC-L1-05 INFO : des lectures techniques non filtrées restituent du contenu

- `backend/src/infrastructure/database/postgres/PostgresGovernanceExceptionReviewRepository.ts:44` (revue d'exception par
  `auditLogId`) et les listes d'exceptions de la santé de la gouvernance (`PostgresGovernanceQueries.ts`,
  `PostgresGovernanceHealthRepository.ts`) lisent `audit_log` sans filtre, par conception (§8.2). Une ligne marquée resterait
  consultable par ces écrans (métadonnées ; le motif est réservé à `audit.read` depuis D6-02). C'est conforme au cadrage, mais
  le texte R5 doit le dire (« disparaît des écrans de consultation du journal », et non de tous les écrans). Décision de
  portée : A15/HUMAN.
