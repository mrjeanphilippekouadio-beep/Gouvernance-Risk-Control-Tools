## Constats

### SEC-Q253-01 : sur un PERIMETRE, un accès sans échéance reste permanent en base (question d'A06)

- Gravité : **LOW 2,2** (`CVSS:3.1/AV:N/AC:H/PR:H/UI:N/S:U/C:L/I:N/A:N`), même classe et même note que SEC-V5-02.
- Confiance : CONFIRMED. Un accès inséré sous runtime sans échéance sur un risque PERIMETRE donne `visibility_granted = true`. Le même accès sur un NOMINATIF donne `false`, grâce au fail-closed de V5.
- Deux façons d'y arriver aujourd'hui :
  1. une écriture SQL directe (runtime, script, seed) ;
  2. **la fenêtre de déploiement** : si `npm run migrate` passe 094 avant que le nouveau code ne serve, l'ancien code écrit encore des accès PERIMETRE sans échéance. 094 ne repasse pas sur ces accès, qui deviennent permanents jusqu'au prochain `set` sur le dossier.
- **Ma réponse : à fermer, de préférence dans ce lot.** Le changement porte sur un seul mot dans `visibility_granted` (087) : la condition du cas « sans échéance » `visibility_own_level(...) <> 'NOMINATIF'` devient `= 'CLIENT'`. Il faut reprendre la fonction en entier avec `SET search_path = pg_catalog, public, pg_temp` et l'`ALTER FUNCTION`, et ajouter un test miroir de celui de SEC-V5-02. Après 094, aucun accès PERIMETRE vivant légitime n'est sans échéance : le changement ne coupe donc rien de légitime. Il ferme les deux cas, et l'invariant de base devient le même pour les deux niveaux restreints.
- Si le lot doit rester « données seulement » : pas bloquant. Dans ce cas, (a) déployer le code **avant** la migration, ou relancer 094 (rejouable) après le déploiement ; (b) suivre la redéfinition comme LOW pour A07 dans le prochain lot de base.

### INFO

- **SEC-Q253-02** : l'insertion d'un accès sans échéance reste permise par la garde 087 ; c'est l'application qui la date juste après. Si le correctif SEC-Q253-01 est fait, ce n'est plus qu'un état transitoire dans la transaction, sans effet en lecture.
- **SEC-Q253-03** : un accès PERIMETRE resté sans échéance (fenêtre ci-dessus) ne peut pas être renouvelé (« No renewable access ») ; un nouveau `set` sur le dossier le date. Il n'y a pas de blocage, mais ce comportement est à connaître en exploitation.
